## Permanent cases and actual observations

Parent waits for a completed child handshake at each exact phase, then calls `kill("SIGKILL")` and waits
for process closure. On Windows Node forcibly terminates the process; this is not POSIX signal delivery.
A phase not reached, failed handshake, unexpected normal exit or timeout fails the test.
After termination, the CLI verifies the on-disk log, then a **fresh child process** opens it and attempts
a linked continuation. The original synced prefix must match byte-for-byte in every case.

| Phase | Observed response | Offline verifier exit | Fresh-process recovery | Verdict |
|---|---|---|---|---|
| Before append | None | 0 | One seed record loads; linked continuation succeeds | PASS |
| After a deliberately half-written record | None | 1 | Exit 2; refuses partial tail; file remains byte-for-byte unchanged | PASS |
| After full append, before file sync | None | 0 | Two records visible after process kill; linked continuation succeeds | PASS, process-kill result only |
| After successful file sync, before writer returns | None | 0 | Two records load; linked continuation succeeds | PASS |
| After Boundary result, before response emission | None | 0 | Two records load; linked continuation succeeds | PASS |
| After response emission | Synthetic allowed result | 0 | Two records load; returned receipt matches persisted second record exactly; linked continuation succeeds | PASS |

Every successful restart is independently checked with `verifyReceiptChain`, receipt count, original
seed hash and continuation `prevHash`. The partial case also compares the entire damaged file after
refused recovery: no trimming, reset or repair is allowed.
A full record surviving kill before sync means the OS still exposed those bytes; it does not prove they
would survive a machine/power failure. A persisted allow receipt without a response remains possible
and is not proof that a caller received data.
